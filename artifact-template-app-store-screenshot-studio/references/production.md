# 分层商店图生产规范

## 1. 证据与竞品

检查工程说明、入口、实际页面、原生控制层、订阅边界及已有摄影输出。制作“卖点—实现路径—截图状态—限制”小表，不凭旧商店文案确认功能。

用户要求参考竞品时，浏览真实 App Store 页面，记录 3–5 个同类产品的页面链接、查询日期及可借鉴的构图原则：大标题、视觉节奏、设备占比、收益表达。不要复制品牌资产、照片或原文，不把搜索结果描述当作已经看到的截图。

每次按目标设备查询官方规格：
https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications

1320×2868（iPhone 6.9 英寸）、2064×2752（iPad 13 英寸）是此案例使用过的尺寸，不是永久有效的完整规格列表。需查证后再作为本次导出目标。

## 2. 分镜与资产映射

在截图或生成前，给每页定义：

| 字段 | 内容 |
|---|---|
| id / benefit | 唯一标识、一个用户收益 |
| evidence | 实现文件/页面及能力限制 |
| headline | 每个语言的短标题，通常两行以内 |
| ui | 原始截图路径、语言、捕获设备、页面状态 |
| photo | 唯一摄影 ID、用途、来源、权利说明 |
| layers | 背景、摄影、UI、修复、文案、品牌、装饰路径或配置 |
| composition | 手机位置/宽高/旋转、裁切、标题框、间距 |
| mock | 遮罩位置、替换理由、未改动区域；没有则为 null |

目录可采用 `source/`、`assets/{ui,photos,backgrounds,fonts,brand,retouch}`、`zh-Hans/`、`en-US/`、`contacts/`。不要把参考 PNG 当作可编辑源文件本身。

## 3. 截图与摄影

- Flutter 使用临时副本和固定非空数据；原生相机优先连接设备。记录系统版本、屏幕尺寸、App 版本、语言、页面及操作状态。
- 真实拍摄与 AI 样片可以说明功能，但滤镜“前后对比”必须来自实际滤镜引擎或可追溯成片，不能用两张独立生成图冒充效果。
- 必须更换无意义取景内容时，只替换取景区域，保留相机控制、网格、比例、强度与遮罩边界；留下说明。
- 生成摄影的 brief 描述生活场景、自然光、肤色、曝光、姿态、背景、画面留白与用途。不要自动复制参考人物身份，不要生成带界面文字的整张商店图。
- 将每张图分配独立主摄影；人物、场景、景别和色彩有变化，整体影调协调。亮不等于过曝，肤色和高光保留细节。

## 4. 版式系统

- 用设计 token 管理画布、边距、品牌高度、标题起点、标题字号/行高、UI 主体位置、圆角和阴影。
- 手机尽量竖直且足够大；整套斜放通常不超过 2 张。按 SKILL.md 的完整屏幕规则，同设备界面使用共享宽高比与展示尺寸；变化背景、位置或照片关系时仍保留该比例。用户明确要求局部特写时，才将裁片作为额外视觉元素，不能冒充完整手机界面。
- 弹窗和底部抽屉直接使用打开后的完整屏幕截图，保留底层原页面、真实遮罩和弹窗位置。可额外并列或叠放弹窗前的完整截图；不要抠出弹窗再将其外框作为手机屏幕。
- 充分利用纵向空间但保留呼吸感；不能为了填满牺牲 UI 比例、标题间距或关键信息。默认完整展示手机屏幕，避免通过逐页不同的裁切高度填充版面。
- 顶部只留必要品牌，不默认堆功能小标签和序号。PRO 等影响真实性的标识可放在实际 UI 或合适位置。
- 背景可用低对比艺术色块、弧线、细颗粒或纸纹；避免与标题、面孔、UI 竞争。背景风格服从当前 App，而不是默认黑底/霓虹/玻璃。
- 字体选择明确授权、有完整字形的海报字体。分别设中英文 token；不能用横向拉伸或伪粗体模拟设计。
- 中英文语义等价但不强求逐字翻译。单页字号微调有明确上下限，共享层级，不能逐页任意大小。

## 5. 渲染与复核

可用 HTML/CSS/SVG 加本地浏览器精确渲染。使用确定性 viewport 和 device scale，等待全部图片解码与字体 ready，再截屏。不要依赖截图前固定短延迟。

渲染后转 RGB 并嵌入 sRGB；需先正确转换颜色空间，不能只给非 sRGB 数据重贴标签。导出不覆盖原截图。检查全部输出，而不只是首图。

PNG 验证例（Node 路径应按当前环境发现）：

```sh
node <skill-dir>/scripts/validate-png.mjs --width 1320 --height 2868 --count 8 <output-dir>/zh-Hans
```

该脚本检查格式、尺寸、数量、RGB/Alpha、sRGB 元数据和文件哈希，不分析设计质量、不验证实际色彩转换过程。对导出总览图单独检查，不混入最终上传图目录。

字体和标题可通过浏览器测量 bounding box、scrollWidth/clientWidth 与字体加载情况；两行文字必须人为确认断行和语义。截图重复检测需要同时检查素材映射与目视相似内容。

记录每页 UI 容器的 x/y、宽高和原图尺寸，检查同设备比例及展示尺寸一致，并检查图片没有负偏移或固定高度造成的非预期裁切；弹窗页再目视确认底层页面与弹窗同时保留。

限定修订可输出冻结项校验报告；定版可记录所有依赖文件 SHA-256，之后先 verify 而不是自动刷新基线。仅用户确认后的新定版才重录基线。
