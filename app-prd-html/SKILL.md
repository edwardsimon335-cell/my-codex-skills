# App 功能需求 PRD

交付让研发快速看清「本次改什么、何时触发、界面如何变化、做到哪一步」的文档。默认生成可离线打开的 HTML，并按用户已指定的统一目录交付；仅本地草稿或用户指定其他格式时遵循当次范围。不要将源项目的功能、供应商、商品或行业规则套用到新项目。

## 先辨明现状和本次变化

- 读取用户提供的现有文档、相关页面与最小必要代码，确认入口、状态、跳转、权限和数据保留行为。只看与本次需求有关的实现。
- 区分已实现行为、用户要求的新行为、尚待确认的行为。未知规则标在对应功能旁，不编造接口、价格、产品标识或完成情况。
- 源代码与目标要求冲突时写清当前与目标；更新文档不等于完成代码。用户明确指定状态变更时更新标记，并检查同一功能的旧备注是否矛盾。
- 用户说后续提供文档的集成，只留链接位置；除非另有要求，不展开事件、参数、协议或技术实现。
- 已有文档优先原位迭代，保留用户填入的链接、截图、动效和确认过的文案。仅缺少关键决策时提问，其他部分继续整理。

## 写法与信息结构

1. 顶部放标题、**需求背景**和**本期目标**。背景说明当前能力与缺口；目标说明这次交付后的具体变化。各一小段，比正文略醒目，避免一句口号或长篇论证。
2. 正文按本次开发的**功能点**组织章节，名称具体可定位。相关的现有体验放在该功能下说明复用关系，不单列一章散乱的截图库。
3. 每项写足「触发条件 → 行为变化 → 结果/返回位置」，只补充会改变研发实现的例外。能两句说清的集成不扩成流程图。
4. 并列规则优先表格：入口/条件/交互；能力/变化前/变化后；选项/标识/展示/操作文案。按需选用，不为凑齐结构增加不存在的业务。
5. 关键按钮用真实文案；多个选项的选中态放同一行对照，移动端横向滚动。资格与展示分支写成逻辑，不擅自新增产品或记录类型。
6. 少写泛化价值、重复总结、实现流水账。默认不附验收清单、技术架构或冗长风险章节；用户要求或关键规则确实需要时再加入。

## 页面、状态和动效

- 页面证据优先使用实际 App 截图、模拟器/设备截图或现有 UI 组件的真实渲染；用演示数据，移除个人信息、凭证和客户数据。
- 截图紧邻对应功能。触发场景可在表格行内「查看页面」展开；变化前后可用成对截图；图片点击放大，关闭后保持阅读位置。
- 多状态以按钮切换，标题、图像、说明同步。没有实现的页面标为「设计示意」；没有截图时明确写「页面待补充」。不要用重新绘制的 HTML、AI 图或静态贴图冒充实际 App 页面或实际动效。
- 动效有理解价值且有素材时嵌入真实录屏或真实组件逐帧视频，提供播放、暂停、重播和静态状态。默认不自动播放、不循环，切换静态图或离开页面时暂停；减少动态效果时仍可阅读静态内容。
- 无法取得素材时先完成可确认内容，列出具体缺项。不要为了写 PRD 擅自集成业务代码、发起购买或修改真实用户数据。

## 默认 HTML 版式

- 桌面左侧固定目录，右侧浅灰底内容区；白色圆角表格与截图卡片。使用项目的文字品牌或用户指定色，无来源时用克制的中性色和单一强调色。
- 目录按顺序编号并显示功能状态，点击跳转、滚动高亮。待开发/待接入/待补充用橙色，已完成用绿色；正文和目录从同一状态数据生成。「已完成」需有用户确认或可靠依据，截图存在不等于全链路完成。
- 左栏底部仅显示文档更新时间，不堆备注、打印或导出按钮。更新时间取用户所在时区的实际更新时间，不沿用旧版本日期。
- 背景/目标约 16px，正文约 14px，次要备注不低于 12px；截图保持比例，可放大阅读。窄屏目录改横向滚动，表格和对照行内部滚动，页面本身不横向溢出。
- 若需补文档链接，输入框置于相应功能下。保留已填内容，并在该处提供「导出含链接的 HTML」；不要只靠浏览器本地存储交付。

## 统一目录与发布

后续项目统一归入现有需求目录。涉及新项目、版本登记、发布或在线更新时，读取 [统一目录发布规则](references/publishing.md)。这是用户指定的个人发布目的地，不是新项目的业务规则。已有线上文档的更新应同步目录与在线版本；明确要求仅本地或草稿时不发布。

- 目录采用左侧项目、右侧版本需求两层结构；使用圆角悬浮侧栏、克制的半透明材质和紧凑面包屑。手机端使用顶部项目选择器。
- 项目徽标显示完整项目编号，一般为 2–3 个大写字母 + 2 位数字，如 AB01、XYZ02。根据项目资料确认编号；不得截成首字母、漏数字或猜编号。文字由 HTML 渲染，4–5 位均完整可读。
- 目录左下显示「产品经理：黄浩宇」。这是目录页信息；PRD 左下仍只显示文档更新时间。
- 每份 PRD 左侧最顶部提供「返回目录」，指向 `/projects/<id>/`，返回后保持对应项目选中。
- Imagegen 可用于目录品牌插画等装饰素材；当前只替换「需求文档」标题前的品牌图标，保留版本列表的文档图标。用生成图补充视觉，不替代真实截图、数据图表或准确文字。已有原生 SVG 图标不因使用 Imagegen 而整套重做。

## 生成与交付

需要新建 HTML 时，读取 [数据格式与组件](references/html-data.md)，使用随附模板和标准库脚本。无需安装第三方包，路径不依赖当前项目：

```sh
python3 <skill目录>/scripts/build_prd.py \
  --input <项目目录>/prd.json \
  --output <交付目录>/产品需求.html \
  --timezone <用户时区>
```

[中性示例](assets/example.json)仅展示结构，必须替换成当前项目内容；没有适用的章节就删掉。可按需求调整 [HTML 模板](assets/prd-template.html)，不要为轻微修改重建现有文档。

生成器将图片和视频内嵌，可单文件交付；素材较大时按交付渠道决定是否改用相对路径包。保留可编辑数据与相对路径素材，便于下一轮修改；交付目录按用户指定位置，未指定则放当前工作区。

交付前实际打开并抽查：目录定位、状态一致、图片放大、展开收起、状态切换、视频重播、已填链接导出后再打开、窄屏排版。确保「真实页面」有来源，新增内容没有带入原项目标识或敏感数据。检查结果留在工作记录，不自动变成 PRD 验收章节。若环境无法浏览，说明未完成的视觉验证，不宣称已验证。

最终答复提供目录地址、当前需求直达链接和必要的缺项；迁移 Skill 时可复制整个 `app-prd-html` 文件夹到目标环境的技能目录。
