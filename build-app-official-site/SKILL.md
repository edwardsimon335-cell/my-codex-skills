# App 官网制作

复用工作流与质量标准，不复制所有产品的视觉风格、文案、法律事实或基础设施。把官网视为三项任务的组合：解释产品价值、引导正确下载、承接支持与必要政策信息。

## 1. 先核实，再设计

读取现有站点、仓库说明、已确认产品资料与真实素材。用 [产品输入清单](references/product-brief.md) 提取产品变量。修改既有官网时先记录路由、公开链接、品牌资产、托管方式与分析脚本，不破坏已有 App 或商店引用的地址。

- 区分“当前已上线”“计划功能”“未知”，只把已确认功能写成现有能力。
- 产品语言与沟通语言分开确定；不要因用户用中文沟通就默认官网仅中文。
- 价格、权益、商店链接、支持邮箱、运营主体、SDK 和数据流必须按该产品核实，不继承另一个产品的配置。
- 优先自行查找已有资料；非阻塞缺项可留在内部待办。不可在生产页面发布虚假链接、假评价、编造下载量或占位政策。
- 缺少影响真实性、隐私声明或发布授权的信息时，只问必要问题；可以继续独立的设计与本地实现。

## 2. 确定最小信息架构

先给出短版页面与内容计划，然后实现。默认候选结构不是强制模块清单：

1. 首屏：App 身份、一句具体价值、真实产品视觉、主下载入口。
2. 核心能力：选择 3–5 项与使用动机有关的价值，用真实界面或样例支撑，避免功能流水账。
3. 使用路径：仅在产品需要解释时增加简短步骤，不为填充版面重复功能。
4. 下载收口：只提供已确认平台；未上线平台使用明确状态，不伪造可下载按钮。
5. 支持与页脚：支持渠道、适用政策入口、版权与已确认主体信息。

按实际产品补充 FAQ、兼容性、定价说明、账户删除说明等。把 Guides、免费浏览器工具、前后对比滑杆或其他交互演示作为可选价值模块：只有能帮助用户理解或获得真实结果时才添加。工具的本地/服务端处理与 App 的 AI 能力分别说明，演示不能暗示网站拥有未实现的功能。无可靠证据就不放评分、奖项、用户证言或品牌背书。单平台不硬套双商店布局；没有账号不虚构账户删除功能。

## 3. 复用骨架，保留品牌差异

- 从 App 图标、界面与目标受众提取颜色、字体层级、圆角、间距和图像语言，形成少量设计变量。
- 以产品本身为主角，优先真实截图、经核实的功能演示和已有品牌资产。效果概念图不能冒充真实 App 界面。
- 保持文案简洁，一节表达一个重点；先说明用户收益，再解释技术。避免空泛的“革命性 AI”“无限可能”。
- 手机优先并兼顾桌面；保证截图可读、主 CTA 清晰、长标题不溢出。动效辅助理解，不遮挡内容；尊重减少动态效果偏好。
- 保留产品各自的调性，不将某个案例的深色、渐变、情侣元素或摄影布局固化为通用模板。

## 4. 配套页面必须与真实产品一致

对照 [政策与发布检查](references/release-checklist.md)，确定独立可直达的支持、隐私、服务条款、订阅说明等页面及稳定 URL。已被商店或 App 使用的旧路径要保留或明确重定向。

- 隐私文案依据实际数据收集、用途、处理方、保留/删除和联系方式，不从另一 App 整页复制。
- AI 产品不要宣称未证实的准确率、完全本地、零保存或绝不训练；健康、估价等结论添加与真实能力匹配的边界说明。
- 订阅文案区分免费额度、付费权益、自动续订、取消与恢复；以当前已确认商店配置为准。不要将其他产品价格或试用条件写入。
- 私密空间不等于“不处理数据”；是否公开发布、谁可见、如何删除等分别核实。
- 需要法规或平台政策判断时查阅当前官方资料；说明待确认项，不保证审核通过。大陆上线与 ICP/APP 备案分别处理，不凭服务器城市决定主体属地。

## 5. 实现与部署分离

尊重现有技术栈和用户指定环境；没有动态业务需求时优先轻量静态站，不为展示站添加登录、数据库或支付后台。

- 将产品文案、商店 URL、语言、政策日期与主题集中配置，保持模板可复用、产品配置相互隔离。
- 保留基本页面身份与使用体验：正确 title、favicon、语义结构及可访问正文。这不是默认启用 SEO 的理由。
- **SEO 是可选模块，新站默认不启用，只有用户要求或确认需要自然搜索获客时才启用。** 未启用时不自动增加关键词研究、SEO 文案扩写、搜索落地页、结构化数据、canonical/sitemap/hreflang 或搜索提交任务。已有站点的 SEO 配置不因本模块关闭而删除，也不擅自设置 noindex/robots 屏蔽。
- 启用 SEO 后再按站点需要规划 description、canonical、sitemap、hreflang、结构化数据与搜索内容；不得为凑模块生成空洞关键词页面。社交分享预览按传播需求配置，不是强制 SEO 交付。
- 将语种列表参数化，不照搬案例的语言数量。同步导航、按钮、FAQ、支持与政策内容；不得把英文回退冒充完成翻译。含阿语/希伯来语等语言时检查 RTL 布局、图标方向与混合文字。
- Guides 单独按需启用，提供真实使用价值与相关下载入口；不随 SEO 自动添加，也不因有 Guides 就默认开展 SEO。
- 所有图片使用适当尺寸与压缩，提供必要替代文本；不要为首屏加载全部大图或视频。
- 检查分析脚本是否已存在，避免重复注入；不将启用新跟踪视为默认授权。
- 本地创建或修改不代表获准部署、改 DNS、迁移托管、修改账号权限或创建凭据。保持既有授权范围，不触碰无关 API、Queue、数据库或生产定时任务。

## 6. 验收后交付

执行 [发布检查清单](references/release-checklist.md)，报告实际测过什么与未测什么。验证桌面和手机布局、内部路由、商店与支持链接、政策页直达、构建结果；有可用浏览器时做真实页面检查，不能用 HTTP 200 代替视觉验收。

交付保持简洁：完成内容、预览/文件或已验证上线地址、未解决的真实性/合规/素材缺项、部署状态。只有实际完成并核验后才称“已上线”。不要为展示完整性掩盖阻塞项。
